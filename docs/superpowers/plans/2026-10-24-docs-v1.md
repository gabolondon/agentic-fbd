# Docs v1 Implementation Plan

**Goal:** the minimum markdown documentation in the repo to launch the plugin to the public:
someone landing on GitHub can install it, ask for a first diagram, read every block kind and
field, use the CLI and the viewer, and know how to contribute or report a vulnerability.

**Execution:** Claude (Opus) orchestrates. Each writing task goes to a Sonnet 5.5 subagent at
high effort, and runs in parallel with the others; Claude reviews every page against the code
before it is accepted, then does the integration task itself.

**Out of scope for v1:** a `/docs` section on the website, Spanish docs, overview or executive
diagram levels, the viewer's local HTTP API (internal, may change), issue templates.

## Global constraints

- English only. Plain, short sentences for a smart engineer who has never seen the project.
- Public repo: no client, company-internal code, data or names. Examples come from the repo's own
  examples (`skills/agentic-fbd/examples/`) or are written from scratch and generic.
- Every claim is checked against the source, not against other docs: CLI behavior from
  `packages/cli/src`, validation from `packages/core/src/validate`, fields from
  `skills/agentic-fbd/references/logic.schema.json`. Command output shown in a page is real
  output, produced by running the command (`node dist/cli.mjs …`).
- `skills/agentic-fbd/references/format.md` stays the normative reference, written for the agent.
  Human docs explain and give examples, and link to it for the exact grammar; they don't copy it.
- No marketing tone, no emoji. Code blocks are complete and valid (JSON snippets pass `validate`
  when they are whole files).
- Relative links between pages; every link resolves.

## Tasks

### Task 1 (Sonnet): `docs/blocks.md`

Sources: `format.md`, `logic.schema.json`, `packages/core/src/types`, both examples.

- One section per node kind: `trigger`, `function`, `state`, `decision`, `external`, `result`,
  `group`, `instance`, `pin`. Each has: what it stands for, its fields in a table (field, type,
  required, meaning), a short JSON snippet, and how it looks in the viewer.
- Then: ports and the type syntax, wires (`node.port`, `draw`), groups and unexplored groups,
  `blockTypes` with `body` and pins, `see` links, risks, `types` and `typeInfo`, Design marks
  (`change`, `changeNote`, `before`, `note`).
- Ends with one whole minimal diagram that passes `validate`.
- Done when: every property in the schema appears in the page, and the closing example validates.

### Task 2 (Sonnet): `docs/cli.md`

Sources: `packages/cli/src/main.ts`, `server.ts`, `checkCode.ts`, `checkLinks.ts`, and the
validators in `packages/core/src/validate`.

- Running it: from the plugin (`node <plugin>/dist/cli.mjs`) and from a clone. Node 20+.
- `validate`: several files, `--check-code <repo-root>`, `--json` (show the real JSON shape),
  exit codes 0/1/2. Real output for a valid file and for one with an error.
- `open`: `--port`, `--no-open`, binds to `127.0.0.1`, live reload, serves the other
  `*.logic.json` in the folder, which files the viewer writes (`.layout.json`, `.draft.json`,
  `.review.json`).
- Issue codes table: every code the validators emit, its severity (error, warning, notice), what
  it means and how to fix it. The list is read from the source, not from this plan.
- Done when: every issue code in `packages/core/src` and `packages/cli/src` is in the table.

### Task 3 (Sonnet): `docs/viewer.md`

Sources: the README "The viewer" section, `packages/viewer/src`, screenshots in `docs/images`.

- Reading: structure panel, levels, double-click and Esc, hover and click on wires, the block
  panel, the Data box, labeled connectors, Before/After and Risks, linked diagrams.
- Changing: edits, notes, the draft, Save, Copy for agent, Copy reference for agent, arranging by
  hand and Auto layout, what lands in which file.
- Keyboard and mouse summary table.
- Done when: every control in the viewer's toolbar and panels is named, checked by running
  `node dist/cli.mjs open skills/agentic-fbd/examples/auth-gate.logic.json`.

### Task 4 (Sonnet): `docs/getting-started.md` and `docs/skill.md`

Sources: `skills/agentic-fbd/SKILL.md`, README Install and Use, the examples.

- Getting started: requirements, the two install commands, a first Understand request and what
  happens (file written, validated, viewer URL), going one layer deeper, a first Design request,
  committing the diagram, troubleshooting (Node missing or too old, port in use, the viewer shows
  offline, `validate` errors).
- Skill: the user-facing view of `SKILL.md` (when it runs on its own, when it offers, when it
  stays out), both modes, the files it writes and the ones only the viewer writes, the edit loop
  with the viewer, after implementation. Prompts as examples throughout.
- Done when: nothing in it contradicts `SKILL.md`.

### Task 5 (Sonnet): `CONTRIBUTING.md` and `SECURITY.md`

Sources: README Development, `package.json` scripts, `versions.yaml`, `CLAUDE.md`,
`.github/workflows`.

- Contributing: setup, the checks (`npm test`, `npm run typecheck`, `npm run build`,
  `npm run test:e2e`, `npm run check:dist`), why `dist/` is committed, conventional commits,
  English only, no internal names, examples from scratch, versions are bumped only by release
  commits.
- Security: private report through GitHub Security Advisories, supported version (latest), scope.
- Done when: every command listed runs as described.

### Task 6 (Claude): review, integration and drift guard

- Review each page against the code; send corrections back to the same subagent.
- `docs/README.md` index, README rewrite with the Documentation section, links checked.
- `tests/docs.test.ts` (vitest), three checks:
  - every node kind and every property in `logic.schema.json` is mentioned in `docs/blocks.md`;
  - every issue code found in `packages/core/src` and `packages/cli/src` is in `docs/cli.md`;
  - every relative link in `docs/*.md`, `README.md`, `CONTRIBUTING.md` and `SECURITY.md` points
    at a file that exists.
- Full checks: `npm test`, `npm run typecheck`, `npm run check:dist` (exit 0).
- One commit per page group, then a `docs` release note in the next `chore(release)`.

## Effort

Writing in parallel: about an hour of agent time. Review and integration: one to two hours.
